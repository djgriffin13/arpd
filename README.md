# ARPD Kit: Agentic Research Paradigm Development

**Status:** prototype v0.1 (October 2026). Submitted as the research artifact for a proposal to the
*Organization Science* special issue "AI-Enabled Frontiers in Organizational Science."

## What this is

The ARPD Kit helps a researcher who is not a software developer direct a **team** of AI coding
agents to build a research instrument. Examples of instruments:

- an experimental platform;
- a measurement pipeline for behavioural data;
- a statistical tool for a model that existing software does not support.

The researcher stays in charge of the scientific decisions throughout.

The kit has three parts.

1. **A constitution.** This is a short governing document that every agent reads at the start of every
   session. It assigns authority by subject. It records the researcher's rulings word for word. It
   separates the decisions agents may take from the ones they must bring to the researcher. It also
   defines when something counts as built, tested and *scientifically* validated.
2. **A library of modules.** These are optional additions to the constitution, selected to fit the
   project:
   - **Science modules:** experiment platform, statistical methods, measurement pipeline, simulated
     agents, human-subjects data.
   - **Team modules:** a single agent, a multi-agent team, autonomous mode, cross-repository
     contracts, tiered gates.
3. **A setup interview** (a Claude Code skill). It asks the researcher about the science and proposes
   engineering defaults with their reasons. It then writes the project's governing documents, a
   *paradigm specification* and a first bounded task. Finally, it explains how to work with the team.

## Why "team"

Recent evidence on multi-agent AI systems is mixed: teams of agents often do no better than a single
agent, and sometimes worse. The kit starts from a team-science reading of that evidence. Most of the
systems evaluated so far are **multi-agent workflows**: agents put together without the structure
that makes human teams work. That structure includes:

- clear roles and exclusive authorities;
- leadership that sets direction and holds intent;
- explicit coordination of dependencies;
- monitoring and closed-loop communication;
- a learning loop that changes the team's rules when they fail.

The kit turns a multi-agent workflow into a **multi-agent team** by writing that structure down, in
files the agents read and maintain. Most of the constitution also helps a single agent. That lets the
kit double as a **test bed**: you can compare single-agent and multi-agent work, with and without
the constitution, on the same task (see `evaluation/`).

## Why "scientific validity"

Software can pass every test and still measure the wrong construct, implement a different behavioural
mechanism, or estimate a quantity that cannot support the intended conclusion. So every project
generated by this kit carries a **paradigm specification**. It links each step:

> research question → constructs and mechanisms → operationalizations → scientific invariants →
> requirements → verification evidence (software) → validation evidence (science) → permitted
> conclusions

A requirement moves from *Implemented* to *Verified* on engineering evidence. It becomes *Validated*
only on scientific evidence that the researcher has accepted.

## Quick start

See [QUICKSTART.md](QUICKSTART.md). In short:

1. Copy or clone this repository into a new folder for your project.
2. Open the folder in Claude Code.
3. Type `/arpd-setup`. The interview takes 30–60 minutes.
4. Follow the `START-HERE.md` file it writes for you.

Requirements:

- [Claude Code](https://claude.com/claude-code) with a plan that allows sustained agentic work.
- Git.
- Python 3.8 or later, for the governance checker.

This prototype targets Claude Code. The constitution is plain Markdown, and `AGENTS.md` points other
agent tools to it. Adapters for Codex and other agentic tools are planned.

## Layout

| Path | What it holds |
|---|---|
| `.claude/skills/arpd-setup/` | The setup interview, with its references (interview guide, module catalogue, engineering defaults, team-shape guide) |
| `.claude/skills/arpd-checkin/` | A plain-language check-in: what happened, what is waiting on you, what was decided without you |
| `.claude/skills/arpd-amend/` | Records a ruling, amends the constitution, turns an incident into a rule |
| `kit/constitution/CORE.md` | The core constitution template (always installed) |
| `kit/constitution/modules/` | The module library (installed as selected) |
| `kit/templates/` | Paradigm specification, requirements, status plan, decision ledger, plan template, report templates |
| `kit/agents/` | Role definitions for multi-agent teams (Claude Code subagents) |
| `kit/tools/` | `check_governance.py` (governance checks) and `next_plan_number.py` |
| `evaluation/` | The pilot usability protocol and the protocols for the two planned studies |
| `docs/DESIGN-RATIONALE.md` | Each practice → the coordination problem it solves → its team-science anchor → the evidence for it |
| `docs/WORKING-WITH-YOUR-TEAM.md` | How to direct the team: prompts, check-ins, rulings, walkthroughs |
| `examples/` | A worked example project, with its development trace |

## Where the rules come from

The constitution was distilled from the governing documents of three agent-built research
instruments, about 4,500 commits in total:

- a behavioural-data analytics platform;
- a statistical modelling package;
- its successor application.

It was then reorganized around team-science theory. Each rule in `docs/DESIGN-RATIONALE.md` names:

- the incident or practice it came from;
- the coordination mechanism it is meant to serve;
- whether its benefit has been **tested** or is so far **proposed**.

Most are proposed. Testing them is the purpose of `evaluation/`.
